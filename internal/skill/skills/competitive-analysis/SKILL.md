# 竞品分析框架

好的竞品分析不是"列出一堆竞品的功能"，而是**回答一个具体的产品决策问题**。没有决策目标的竞品分析是浪费时间。

## 先问清楚：为什么要做这次分析

开始前必须回答：

1. **这次分析要支持什么决策？**
   - 要不要进入这个市场
   - 功能要不要做 / 怎么做
   - 定价怎么定
   - 差异化切入点在哪
   - 投资 / 收购可行性

2. **谁是读者？**
   - 老板 / 投资人：重结论和洞察
   - 产品团队：重功能细节和交互
   - 设计师：重视觉和体验

3. **多深？**
   - 快速扫描（1-2 天，3-5 个竞品，各维度浅看）
   - 深度调研（1-2 周，2-3 个核心竞品深挖）

**不同目的决定不同的分析维度和深度**。别上来就套通用模板。

## 竞品选择

### 三类竞品都要看

| 类型 | 定义 | 举例（假设在做 AI 笔记） |
|---|---|---|
| 直接竞品 | 同目标用户、同核心需求、同解决方式 | Notion AI、Mem、Reflect |
| 间接竞品 | 同核心需求但解决方式不同 | 传统笔记（Notion、Obsidian）、AI 助手（ChatGPT） |
| 替代方案 | 用户的"非产品"选择 | Word 文档、手写笔记、不记录 |

忽略间接竞品和替代方案是大坑——很多用户最后选了这些而不是竞品。

### 选几个

- 深度分析：**2-3 个核心直接竞品**就够了，多了看不过来
- 快速扫描：**5-8 个**
- 边界参考：各选 1-2 个间接竞品和替代方案

## 分析维度

根据目的选 5-8 个维度，**不要全选**。常见维度：

**产品层**
- 核心功能覆盖
- 独特功能 / 杀手锏
- 用户体验与设计
- 性能和稳定性
- 平台覆盖（Web / 桌面 / 移动）
- 集成生态（API / 插件 / 第三方）

**商业层**
- 定位与目标用户
- 定价模型
- 商业模式
- 用户规模 / 增长速度
- 融资情况

**市场层**
- 品牌感知
- 用户口碑（评论、社区、NPS）
- 营销渠道
- 内容策略

**技术层**（如果是技术驱动型产品）
- 核心技术栈
- 技术壁垒
- 专利 / 开源策略

## 三种核心分析工具

根据决策类型选工具。

### 工具 1：功能对比矩阵（Feature Matrix）

**用途**：功能规划、判断差距和机会点

```
| 功能            | 我们 | 竞品A | 竞品B | 竞品C |
|----------------|------|-------|-------|-------|
| 核心功能 X      | ✅    | ✅     | ✅     | ❌     |
| 核心功能 Y      | ⚠️    | ✅     | ⚠️    | ✅     |
| 差异化 Z        | ✅    | ❌     | ❌     | ❌     |
| ...            | ...  | ...   | ...   | ...   |
```

标记规则：✅ 完整支持，⚠️ 部分支持或体验差，❌ 不支持。

**避免的坑**：不要把矩阵当结论。真正有价值的是"我们有什么别人没有、别人有什么我们缺"这两个问题的答案。

### 工具 2：定位图（Positioning Map）

**用途**：判断市场空白、差异化切入点

选两个**对用户决策最重要**的维度，画二维坐标图，标注各竞品位置。

常见维度组合：
- 专业度 × 易用性
- 功能广度 × 深度
- 价格 × 价值
- 个人使用 × 团队协作

**关键**：选的维度必须是用户会为之付费或转移的。"有没有暗色模式"就不是好维度。

### 工具 3：SWOT / 4P 分析

**用途**：整体战略判断

SWOT（针对自身）：
- **Strengths**（优势）：独特资源、能力
- **Weaknesses**（劣势）：相对竞品的短板
- **Opportunities**（机会）：市场趋势带来的空间
- **Threats**（威胁）：竞品动作、外部风险

只在需要战略层决策时用，不要对每个竞品都做 SWOT——那是把深度分析稀释成流水账。

## 信息来源

按可信度排序：

1. **直接使用竞品**：最重要。官网说的和实际产品体验往往不一致。注册账号真用 1 小时。
2. **产品更新日志 / changelog**：看竞品在往哪个方向迭代
3. **用户评论**：App Store、G2、Capterra、知乎、Reddit 评论。特别关注负面评论——那是机会
4. **招聘 JD**：竞品在招什么人能反映技术方向和团队规模
5. **官方博客、发布会**：策略和定位信号
6. **融资新闻、财报**：规模判断
7. **行业报告**：作为背景，不要当真相

**警惕**：
- 官网宣传 vs 实际产品体验经常差很远
- 别只看公开信息，和目标用户聊过比看 10 份报告更有价值

## 输出结构

报告按以下顺序组织：

### 1. 结论先行（Executive Summary）

**半页以内**，回答最初那个决策问题。一个具体的建议 + 三条核心依据。如果老板只读这半页，也能做决策。

### 2. 背景与方法

- 分析目的（回答的决策问题）
- 选了哪些竞品、为什么
- 选了哪些维度、为什么
- 信息来源和局限

### 3. 竞品概况

每个竞品一段话：定位、目标用户、核心价值主张、规模。不要在这里堆功能。

### 4. 对比分析

用前面选的工具（矩阵 / 定位图 / SWOT）展示。图表 > 文字。

### 5. 关键洞察

这是分析的**价值所在**。每条洞察要满足：
- **非显而易见**：只看矩阵看不出来，需要综合判断
- **可操作**：能转化为产品或业务决策
- **有依据**：能回溯到具体证据

好洞察示例："竞品 A 虽然功能最全，但用户评论高频抱怨性能问题；竞品 B 功能窄但专注，NPS 最高。说明在这个市场'做少但做精'比'大而全'更有机会。"

### 6. 行动建议

根据洞察给出具体的行动建议：
- 短期（本季度）做什么
- 中期（半年）布局什么
- 长期（一年以上）探索什么

## 常见陷阱

| 陷阱 | 症状 | 修正 |
|---|---|---|
| 没有决策目标 | 分析做完不知道有什么用 | 开始前先定义要回答的问题 |
| 只看直接竞品 | 错失间接竞品和替代方案的威胁 | 至少覆盖三类 |
| 只看功能不看体验 | 矩阵打满 ✅ 但实际体验差很远 | 必须真用过产品 |
| 只看表面 | 抄竞品官网文案 | 看用户评论、招聘、changelog 挖深层 |
| 没有洞察 | 只有描述没有"所以呢" | 每个对比后必问"这意味着什么" |
| 维度太多 | 20 个维度，每个浅尝辄止 | 选 5-8 个聚焦 |

## 快速起草清单

动手前先回答：

1. 这次分析要支持什么具体决策？
2. 读者是谁？他们关心什么？
3. 要分析几个竞品？三类覆盖了吗？
4. 挑哪 5-8 个维度？
5. 用哪种工具：功能矩阵 / 定位图 / SWOT？
6. 信息从哪里来？能真用过竞品吗？
7. 期望得到什么结论？（预判一个答案，分析过程中验证或推翻）

最后一条特别重要——**先假设一个答案，再用分析验证**，比没有假设地"开放式研究"效率高得多。
