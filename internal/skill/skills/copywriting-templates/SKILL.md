# 文案写作模板

好文案不是"有文笔"，而是**在读者分心的瞬间抓住他，然后让他采取行动**。这需要结构、洞察和删改，不是辞藻。

## 开始写之前

回答这 4 个问题，文案方向就定了一半：

1. **读者是谁？** 越具体越好。"独立开发者" 比 "开发者" 好，"在 Product Hunt 看到产品的 solo developer" 更好
2. **他们现在在担心 / 想要什么？** 不是你卖什么，是他们此刻在想什么
3. **我们的产品能帮他们做到什么？** 用他们的语言，不是产品说明书
4. **读完希望他们做什么？** 点击、注册、购买、分享？一次文案只追求一个动作

回答不出来就不要动笔，先去做用户研究。

## 核心原则

### 1. 讲利益不讲功能

用户不关心"支持 OAuth2.0"，关心"5 秒登录"。

| 功能描述（差） | 利益描述（好） |
|---|---|
| 支持 10 种文件格式 | 不管你从哪里来，数据都跟着你 |
| AI 辅助生成 | 从空白到初稿，5 分钟搞定 |
| 云端同步 | 在任何设备上继续你的工作 |
| 开源免费 | 你自己掌控你的数据和工具 |

**转换公式**：功能 → "所以呢？"——问三次，直到挖到情感或结果层面。

### 2. 具体胜过抽象

"快" → "3 秒出结果"
"简单" → "三次点击完成"
"强大" → "用 Notion 做到的事，这里只要一半步数"

### 3. 能删就删

每写完一段，问：删掉这句会影响意思吗？不影响就删。

"我们致力于为用户提供最优质的产品体验" → 删。
"最专业的 XX 解决方案" → 删。
"革命性的创新" → 删。

这些套话是噪音，占用了读者的耐心预算。

### 4. 单一焦点

一篇文案追求一个动作：注册 / 购买 / 分享 / 阅读。**不要**既想让人注册又想让人下载 app 又想让人加微信。

## 核心框架

根据文案类型选框架。

### 框架 1：AIDA（经典漏斗）

**适用**：落地页、长文案、邮件营销

```
Attention  (注意) — 第一眼抓住人
Interest   (兴趣) — 让他们看下去
Desire     (欲望) — 想要得到
Action     (行动) — 点击/购买/注册
```

示例（AI 笔记产品落地页）：

- **A（头条）**："再也不用在 10 个笔记软件之间复制粘贴。"
- **I（副标题）**："LiteFlow 用 AI 自动串联你的所有想法、文档和代码，一个地方找到所有东西。"
- **D（演示）**："用户平均找回资料的时间从 3 分钟降到 8 秒。" + 动图演示
- **A（CTA）**："免费注册，导入你的第一个笔记 →"

### 框架 2：PAS（痛点驱动）

**适用**：社交媒体、短文案、B2B 营销

```
Problem     (痛点) — 点出用户当下的问题
Agitation   (放大) — 让问题变得具体、紧迫
Solution    (方案) — 给出解决路径
```

示例（PM 工具）：

- **P**："你今天开了 4 个会，做了 0 件实事。"
- **A**："每周 15 小时在会议上消失，你的项目一直在延期，team 在抱怨，老板在催。"
- **S**："Linear 让你把讨论、决策、任务放在一起，会前 5 分钟对齐就能开始干活。"

### 框架 3：4U（头条优化）

**适用**：标题、Hook、广告语

一个好标题至少要有 4U 中的 **两个**：

- **Useful** (有用)：对读者有实际价值
- **Unique** (独特)：和别人说的不一样
- **Urgent** (紧迫)：为什么现在读
- **Ultra-specific** (极具体)：数字、名字、事件

对比：

| 普通标题 | 4U 强化 |
|---|---|
| 如何提高工作效率 | 一位 solo developer 用 3 个习惯把每周产出翻倍（Useful + Specific） |
| 我们的产品发布了 | LiteFlow 今天上线：用 AI 把你的知识库变成搜索引擎（Unique + Specific） |
| 学习写作技巧 | 为什么你的文案没人点？3 个你在重复犯的错（Useful + Urgent） |

### 框架 4：BAB（故事化）

**适用**：案例故事、用户证言、博客开头

```
Before  (之前) — 用户之前的状态（痛苦的）
After   (之后) — 使用产品后的状态（美好的）
Bridge  (桥梁) — 如何过渡的（你的产品）
```

示例（生产力工具）：

- **Before**："Lisa 是一位独立设计师，每天在 Figma、Notion、微信、邮件之间切换 50 次，每晚收工时精疲力尽。"
- **After**："现在她每天专注时间从 2 小时增加到 5 小时，客户回复变快，接单量翻倍。"
- **Bridge**："她用 LiteFlow 把所有工具的通知和任务汇总到一个收件箱，每小时只看一次。"

## 具体场景模板

### Hook（社交媒体开头 / 短文开头）

第一句决定了用户是否继续读。三种有效 Hook：

1. **反常识**："每天写代码 10 小时的人，产出往往最低。"
2. **具体痛点**："你有多少次因为找不到一年前的笔记而重写？"
3. **意外承诺**："我用了一周把 GitHub Star 从 50 做到 5000，下面是具体做法。"

避免：
- "大家好！" / "今天和大家分享"
- 自我介绍（读者不关心你是谁，关心你说什么）
- "我最近在思考一个问题..."（别人没时间听你思考）

### Slogan / Tagline

好 slogan 的 3 个标准：

1. **一句话说清价值**
2. **能复述，会转述**（有记忆点）
3. **只属于你**（竞品不能照抄）

公式：

- **对谁 + 做什么 + 有什么不同**
  - "给独立开发者的一体化知识管理 — 不需要再切换工具。"
- **动词开头 + 结果**
  - "Ship, faster." (Linear)
  - "Think better." (Notion AI)
- **反常识声明**
  - "The developer-first coding font." (不针对设计师的声明反而吸引开发者)

### 产品介绍（1 段话版）

```
[产品名] 帮助 [目标用户] [核心动作]，让 [核心结果]。
不像 [竞品 / 替代方案]，我们 [差异化]。
```

示例：
"LiteFlow 帮助独立开发者把分散在 10 个工具里的知识汇总到一个 AI 驱动的工作台，让你在需要时一秒找到它。不像 Notion 那样让你手动整理，我们让 AI 帮你归类和关联。"

### CTA（行动召唤）

弱 CTA：
- "了解更多"
- "点击这里"
- "提交"

强 CTA：
- 具体 + 零风险："免费试用 14 天，不需要信用卡"
- 结果导向："开始节省 5 小时/周"
- 紧迫感（仅真实时使用）："前 100 位免费"

## 常见陷阱

| 陷阱 | 症状 | 修正 |
|---|---|---|
| 讲功能不讲利益 | 罗列特性，用户"所以呢？" | 用"所以呢"测试，挖到结果 |
| 受众太宽 | "为所有人打造" | 越窄越好，反而更打动目标用户 |
| 套话太多 | "专业"、"优质"、"高效" | 换成数字或具体场景 |
| 目标太多 | 既想卖货又想涨粉 | 一篇文案一个行动 |
| 自吹自擂 | 通篇"我们有、我们是、我们能" | 改写成"你会、你能、你获得" |
| 没有对比 | 读者不知道你哪里不一样 | 明确差异化（"不像 X 那样 Y"） |
| 标题平淡 | 没人点开 | 用 4U 检验，至少满足两个 |

## 起草清单

动笔前回答：

1. 目标读者是谁？（具体到能想象出一个人）
2. 他此刻在担心 / 想要什么？
3. 我的产品能帮他做到什么？（用他的语言）
4. 读完希望他做什么？（一个动作）
5. 用哪个框架：AIDA / PAS / 4U / BAB？
6. 我的差异化是什么？（为什么选我不选竞品）
7. 一句话 slogan 是什么？

回答完再开始写。先把核心信息用大白话写出来，然后套框架、删废话、打磨措辞。
