# 研究方法论

普通的"搜一下资料"和真正的研究差别在：**前者累积信息，后者产生洞察**。这个 skill 帮你从前者升级到后者。

## 开始之前：定义研究问题

最大的研究失败是**问题定义错了**。错的问题再努力也得不到有用答案。

### 好研究问题的 4 个特征

1. **具体**："AI Agent 现在发展得怎么样" → 差 / "多 Agent 编排在 2024-2025 有哪些主流架构模式" → 好
2. **可验证**：有明确的回答形式（列表、对比、结论），而不是无底的"探索"
3. **有目的**：回答后能支持某个决策或行动
4. **可完成**：有时间边界，不是无止境的"持续关注"

### 研究问题分类

不同类型用不同方法：

| 类型 | 示例问题 | 适合方法 |
|---|---|---|
| 现状类 | "当前 X 领域的主要玩家有哪些" | 横向扫描 + 市场地图 |
| 对比类 | "A 和 B 的技术优劣" | 维度拆解 + 对比矩阵 |
| 趋势类 | "未来 2 年 X 会怎么发展" | 时间轴 + 信号追踪 |
| 因果类 | "为什么 X 成功 / 失败" | 案例研究 + 多因素分析 |
| 可行性类 | "做 X 有没有机会 / 风险" | SWOT + 场景分析 |
| 学习类 | "X 是什么、怎么运作" | 从核心概念到应用 |

开始前先确定你的问题是哪类，避免用错方法。

## 研究流程

### 阶段 1：框架搭建（10-20% 的时间）

**不要直接开始搜索**。先花时间画骨架。

步骤：
1. **拆分主问题为子问题**：主问题下有 3-5 个子问题，每个都可独立回答
2. **预判答案结构**：你期望最终输出是什么形式？列表？对比？时间轴？
3. **识别盲区**：你已经知道什么？不知道什么？知识缺口在哪？

示例（研究"多 Agent 架构"）：

```
主问题：多 Agent 编排在 2024-2025 的主流架构模式

子问题：
1. 有哪些主要架构模式？（现状）
2. 不同模式的 trade-off？（对比）
3. 哪些已经在生产环境验证？（成熟度）
4. 哪些是学术原型，离落地有多远？
5. 下一步可能的演化方向？（趋势）

预期输出：
- 一张架构模式对比表
- 3-5 个代表性项目的深度剖析
- 一段趋势判断

已知：Claude Code、AutoGPT、多 Agent 会议等概念
未知：具体工程实现细节、token 管理策略
```

**骨架搭完，研究就完成了 30%**。

### 阶段 2：信息收集（50-60% 的时间）

### 信息源优先级

按可信度和信息质量排序：

1. **一手资料**
   - 论文（arXiv、Google Scholar）
   - 官方文档 / 技术博客（作者本人写的）
   - 开源代码仓库（实际实现）
   - 访谈 / 播客（作者表达）

2. **二手资料**
   - 技术媒体深度文章（The Verge、TechCrunch、InfoQ）
   - 行业报告（Gartner、CB Insights）
   - 综述文章

3. **三手资料**
   - Twitter / Hacker News 讨论
   - 问答平台（Stack Overflow、知乎）
   - AI 生成的摘要

**原则**：
- 一手资料优先
- 有分歧时追溯到一手
- 别直接引用二手摘要，去读原文

### 检索技巧

- **英文源优先**：英文资料数量和质量都更高
- **多角度搜**：一个主题用 5-10 个不同角度的查询
- **时间过滤**：某些话题只看近 6 个月 / 1 年
- **加特定站点**：`site:arxiv.org`、`site:github.com`
- **追关键作者**：找到领域关键人物，跟踪他们的最新动态

### 资料管理

边搜边整理：
- **每条资料记下**：来源、日期、核心观点、信任度
- **打标签**：按子问题分类
- **做取舍**：不要试图读完所有东西，80/20 原则
- **记录矛盾**：不同来源意见不一时单独记下，后面重点分析

### 阶段 3：综合与洞察（20-30% 的时间）

这是研究**产生价值**的阶段。很多人卡在信息收集阶段，堆了一堆资料没消化。

### 综合方法

**方法 1：对比矩阵**
适用于对比类问题。列出维度 × 对象，填充事实。

**方法 2：时间轴**
适用于趋势类问题。按时间排列事件，看演化规律。

**方法 3：因果链**
适用于因果类问题。从结果反推原因，层层追溯。

**方法 4：分类归纳**
适用于现状类问题。给找到的例子分类，抽象出模式。

### 产生洞察的问题

对着你收集的资料问：

- **共同模式是什么？**（多个案例反复出现的特征）
- **反例是什么？为什么是反例？**（打破共识的案例）
- **没有人提到的是什么？**（被系统性忽略的角度）
- **我最惊讶的是什么？**（反直觉的发现）
- **半年后看回来，最重要的是什么？**（长期视角）

**最好的洞察往往藏在反例和空白中**，不在主流叙述里。

## 研究报告结构

研究产出分两种，选一种：

### 结构 A：决策型报告（支持具体决策）

```
1. 核心结论（1 段）
   回答最初的研究问题，给出明确判断

2. 关键洞察（3-5 条）
   非显而易见的发现，每条带证据

3. 现状描述
   当前这个领域的格局

4. 详细分析
   按子问题展开

5. 局限与不确定性
   还没搞清楚的部分

6. 建议行动
   基于结论，接下来做什么
```

### 结构 B：扫描型报告（建立领域认知）

```
1. 背景（为什么研究这个）

2. 核心概念梳理
   该领域的关键术语和框架

3. 主要玩家 / 方案
   谁在做、做什么、各自的特点

4. 时间轴
   重要事件和演化节点

5. 趋势判断
   接下来可能发生什么

6. 延伸阅读
   推荐进一步学习的资源
```

## 写作原则

- **结论先行**：每节第一段给结论，细节在后
- **数字 > 形容词**：用数据、频次、时间点，少用"很多"、"大部分"
- **引用到具体**：引用时带来源和日期，方便追溯
- **承认不确定**：明确区分"已知事实"和"推测"
- **保留原文关键术语**：英文术语第一次出现时保留原文

## 常见陷阱

| 陷阱 | 症状 | 修正 |
|---|---|---|
| 问题过大 | 研究半年找不到终点 | 拆成可完成的子问题 |
| 只搜不想 | 堆了资料但没整理 | 每天留时间综合 |
| 表面化 | 只看摘要不看原文 | 重要资料读全文 |
| 确认偏误 | 只找支持已有结论的证据 | 主动找反例 |
| 过度依赖二手 | 引用引用的引用 | 追溯到一手资料 |
| 没有洞察 | 只有描述没有"所以呢" | 强制自问"这意味着什么" |
| 结构化不足 | 流水账式输出 | 用对比 / 时间轴 / 因果链 |

## 起草清单

开始前回答：

1. **这次研究要回答的具体问题是什么？**（一句话）
2. **研究结果要支持什么决策 / 行动？**
3. **可以接受的完成标准是什么？**（不能无限研究）
4. **我预期的答案大概是什么？**（有假设才能验证）
5. **最重要的 3-5 个子问题是什么？**
6. **主要去哪些信息源？**
7. **时间预算是多少？**
8. **最终输出是什么格式？**（报告 / 文档 / slides）

回答完再开工。**先假设一个答案，再用研究验证或推翻**——比盲目搜索效率高得多。
