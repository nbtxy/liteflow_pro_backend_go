# 文献综述模板

文献综述的目的**不是把你读过的所有论文列一遍**，而是**为某个具体问题梳理已有工作，并指出空白**。前者是读书笔记，后者是综述。

## 综述 vs 其他研究输出

| 类型 | 目标 | 粒度 |
|---|---|---|
| 文献综述 | 梳理领域已有工作，找出空白 | 多篇文献的对比与综合 |
| 单篇精读 | 深度理解一篇论文 | 一篇 |
| 研究报告 | 回答具体决策问题 | 混合源（论文 + 产品 + 新闻） |
| 技术预研 | 评估技术可行性 | 代码 + 论文 + 实测 |

如果你只是想学习一篇论文，不需要综述模板。综述适合你要覆盖 **5-30 篇** 相关工作的场景。

## 综述流程

### 阶段 1：定义范围（关键！）

动手读论文前，**先回答**：

1. **综述的具体问题是什么？**
   - 差："梳理 AI 领域相关工作"
   - 好："多 Agent 系统中任务分解与调度的主流方法"

2. **时间范围？**
   - 近 2 年 / 近 5 年 / 某个奠基工作后至今

3. **范围边界？**
   - 包含哪些方向？排除哪些？
   - 只看论文还是也看工程文章？
   - 只看主流顶会还是也包括 workshop？

4. **预期读者？**
   - 领域专家（可以假设共识）
   - 跨领域研究者（需要概念引导）
   - 工程师（关心实现而非理论）

5. **最终篇数估算？**
   - 10 篇左右：重点深度
   - 20-30 篇：全面覆盖
   - 50+：需要分层（核心篇 + 背景篇）

**范围没定清楚就开工是大坑**——读着读着跑偏，最后写成了"所有我读过的论文"。

### 阶段 2：收集与筛选

**两步走**：

**第一轮：宽扫描**
- 用 3-5 个关键查询词在 arXiv、Google Scholar 搜索
- 追踪重要论文的引用（往前追祖师爷，往后追继承者）
- 关注关键作者的近期工作
- 收集 30-50 篇候选

**第二轮：筛选核心**
- 读摘要 + intro + conclusion，判断是否相关
- 相关的标为"核心"，相关但次要的标为"背景"
- 剔除明显偏题的
- 最终核心篇数控制在 10-25 篇

### 阶段 3：分类与分析

### 按什么维度分类？

分类维度**服务于综述问题**，不是通用分类法。常用维度：

- **按方法**：基于规则 / 基于学习 / 混合
- **按架构**：中心化 / 去中心化 / 分层
- **按时间**：2020 年前 / 2020-2022 / 2022 至今
- **按应用场景**：研究型 / 生产型
- **按规模**：小模型 / 大模型
- **按开放性**：开源 / 闭源 / 论文仅

**选 1-2 个主维度 + 辅助维度**。维度太多就失去结构。

### 每篇论文要提取的信息

做结构化笔记，字段至少包括：

```
标题：
作者 / 机构：
发表时间 / venue：
一句话概括：

核心贡献（具体）：
1.
2.

方法要点：
- 关键技术
- 创新点
- 数据 / 实验规模

与其他工作的关系：
- 基于哪些前人工作
- 与谁相比做了什么改进

局限：

我的评价：
```

**要点**：
- "一句话概括"强迫你真正理解
- "与其他工作的关系"是综述的核心信息
- "我的评价"是洞察的来源（客观描述之外的主观判断）

### 阶段 4：综合与写作

## 综述报告结构

按以下结构组织，**前 3 节必写**。

### 1. 引言（Introduction）

- **问题背景**：这个领域要解决什么问题，为什么重要
- **综述范围**：明确你要覆盖什么、不覆盖什么、为什么
- **综述结构**：告诉读者后面怎么组织
- **核心结论预告**：一两句话预告综述的核心发现

**注意**：引言写得清楚，后面的阅读负担就小很多。

### 2. 背景与定义（Background）

- 关键术语和概念
- 问题的形式化定义
- 评估指标（如果领域有标准指标）
- 基础方法（后面方法都建立在此之上）

### 3. 主要工作分类综述（Main Body）

按你选的分类维度组织。每一类开头：

- 该类方法的**共同特征**
- 代表性工作（3-5 篇）
- 该类方法的**共同优缺点**

然后逐篇 / 逐组介绍代表性工作：
- 核心贡献
- 关键方法
- 结果数据
- 不足

**写作技巧**：
- 不要按论文发表顺序罗列，按**思想演进**组织
- 多用对比，少用并列
- 每两三篇后加一段"小结"，沉淀发现

### 4. 横向对比（Comparison）

这是综述的**独特价值**。用一张大表 + 一段分析。

```
| 方法 | 发表年 | 核心贡献 | 规模 | 性能 | 开源 | 局限 |
|------|--------|----------|------|------|------|------|
| A    | 2023   | XX       | 10K  | 85%  | ✅    | XX   |
| B    | 2024   | YY       | 100K | 92%  | ❌    | YY   |
...
```

表下面写 2-3 段对比分析：
- 哪些趋势在演化（规模 / 方法 / 效率）
- 哪些问题被反复研究
- 哪些方向有明显改进

### 5. 空白与开放问题（Gaps & Open Questions）

综述的**精华所在**。列出：

- **尚未被研究的子问题**
- **方法上的局限**（所有方法共有的短板）
- **应用边界**（哪些场景还没解决）
- **可能的研究方向**

这节是综述区别于"论文罗列"的关键。没有这节的综述就是汇总笔记。

### 6. 结论（Conclusion）

- 重申综述问题和范围
- 总结主要发现（3-5 条）
- 对领域未来的判断

### 7. 参考文献（References）

- 按论文重要性分层（核心 / 重要 / 背景）
- 按字母或时间顺序排列
- 格式统一（APA / IEEE 等）

## 写作原则

### 1. 用观点组织内容，不是按论文组织

**差**：
```
论文 A 做了 X。
论文 B 做了 Y。
论文 C 做了 Z。
```

**好**：
```
在任务分解上，早期工作依赖规则（论文 A），近年转向 LLM 驱动（论文 B、C）。
但两种方法各有局限：规则不够灵活，LLM 不够稳定。
这促使最新工作尝试混合架构（论文 D、E）。
```

### 2. 建立概念的"地图"

读者读完综述，应该在脑中形成一张**方法之间的关系图**：哪些是基础、哪些是扩展、哪些是替代方案。

### 3. 承认局限

- 你读的论文不全面
- 英文 / 中文资源有差异
- 某些领域快速演化，几个月就过时

提前说明这些，综述的可信度反而高。

### 4. 引用要准确

- 引用原文要对（不要误读摘要）
- 数字要复查（实验结果、性能指标）
- 区分"论文声称"和"你的判断"

## 常见陷阱

| 陷阱 | 症状 | 修正 |
|---|---|---|
| 范围太宽 | "XX 领域所有工作" | 收窄到具体子问题 |
| 流水账 | 按发表时间逐篇介绍 | 按思想演进重组 |
| 只描述不对比 | 每篇单独介绍，没有横向 | 加对比表 + 分析 |
| 没有空白 | 只总结已有工作 | 必须有"gaps"节 |
| 观点不清 | 平铺直叙，像 Wiki | 加入综述作者的判断 |
| 引用不准 | 转述的转述 | 追溯到一手论文 |
| 过时 | 一年前的综述写近况 | 明确时间边界 |

## 快速起草清单

动手前回答：

1. **综述要回答的具体问题是什么？**
2. **时间范围？为什么这个范围？**
3. **包含和排除的边界是什么？**
4. **读者是谁？他们的先验知识如何？**
5. **核心分类维度是什么？**
6. **预计核心论文数量？**
7. **最终输出格式？**（技术报告 / 论文 related work / 博客）
8. **你预判的空白 / 开放问题是什么？**（假设再验证）

回答完再开始收集论文。**先有假设，后有证据**，效率比"读了再说"高得多。
